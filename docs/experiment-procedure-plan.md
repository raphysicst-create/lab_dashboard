## 구현 순서

1. **1,276개 활동의 대응표를 만든다.** 프로젝트 안에 `outputs/review/procedures/`를 두고 기존 활동 ID를 키로 삼는다. 각 행에 교재·판본, 원본 PDF 식별자, 인쇄 쪽과 PDF 물리 쪽(1부터 시작), MD 후보와 해당 소제목을 기록한다. 원본 파일 해시는 파일별로 한 번 기록한다. 후보 검색에는 교재·쪽·활동명·준비물을 사용한다. 사이트 표시 학년, 제목 유사도, 성취기준 또는 출판사 이름만으로 확정하지 않는다. 천재(임성숙) 92개는 해당 판본 전용 실험 MD가 없어 기존 행별 기록과 K7·K8 PDF에서 시작한다.

2. **12개로 작성 방식을 먼저 검증한다.** 기존 중학 4개, 지학사·YBM 중학 4개, 고1 4개를 선정한다. 위 네 사례를 포함하고, 남은 칸에는 천재 저자판, 단원별 PDF, MD 후보가 없거나 여러 개인 활동, 한 쪽에 나란히 실린 활동, 자료 해석·제작을 넣는다. 작업자는 PDF의 학생 지면과 필요한 다음 쪽·그림까지 보고 행동을 순서대로 짧은 한국어로 쓴다. 지시가 하나면 한 단계로 두고, 원본의 하위 활동이 구분되어 있으면 그 구분을 살린다. 동일 주제라도 다른 책의 절차를 전용하지 않는다.

3. **검토를 통과한 과정만 공개 데이터로 만든다.** 검토 기록에는 단계별 근거 쪽과 지면 위치, 작성문, 상태(`검토 대기`·`확인`·`보류`), 보류 사유를 둔다. 수치·단위·순서·선택 조건·학생에게 명시된 안전 지시는 원본과 대조한다. 본문과 그림이 충돌하거나 핵심 도판·부록이 없어 지시가 불완전하면 해당 활동 전체를 보류한다. 준비 목록이나 필요 수량을 과정에서 계산하지 않는다. 변환기는 확인된 문장만 `site/dist/data/procedures.json`으로 내보낸다. 각 활동 ID의 값은 순서가 있는 묶음 목록(`heading`, `steps`) 또는 `null`이다. 묶음 제목은 원본에 필요할 때만 쓴다. 검토 근거, PDF·그림, 위키 원문은 배포 파일에서 제외한다.

4. **로컬에서 활동 상세에 붙인다.** [활동 상세 코드](../site/dist/app.js)의 `showActivity()`에서 준비물 다음에 **탐구 과정**을 배치한다. 단계는 모바일에서도 읽을 수 있는 번호 목록으로 표시한다. 과정 JSON은 상세 첫 진입 때 한 번 요청하고 재사용한다. 제목과 준비물은 먼저 표시한다. 데이터가 `null`이면 ‘미확인’, 파일 요청 실패면 과정 영역에만 재시도를 표시한다. 창을 닫거나 다른 활동으로 이동했을 때 이전 응답이 남지 않게 하고, 약품 자료는 독립적으로 로드한다. 목록·검색창·필터에는 과정을 추가하지 않는다.

5. **교재·단원별로 확대한다.** 표본에서 원문 대조와 화면 검증이 끝나면 위키 후보가 명확한 활동부터 처리한 뒤, 후보가 여러 개거나 PDF에서 직접 작성해야 하는 활동을 검토한다. 묶음마다 두 번째 검토에서 원문과 단계의 순서·조건·범위를 확인한다. 상태별 건수와 보류 이유를 기록해 다음 작업이 중간에서 이어지게 한다. 기존 원자료·통합 JSON·검토 엑셀에 대한 수정은 이 계획에서 수행하지 않는다.

## 완료 기준

- **자료 검토** — 최종 대응표와 공개 데이터에 기존 ID 1,276개가 정확히 한 번씩 있고, 모든 활동이 확인 또는 사유 있는 보류로 정리돼 있다. 공개 과정은 같은 판본의 학생 지면에서 각 단계를 다시 찾을 수 있다. 보류 값은 `null`이다.
- **데이터 검증** — 중복·누락 ID, 빈 단계, 순서 유실, 위키 링크·로컬 경로·내부 근거의 공개를 검사한다. 별도 변환기를 반복 실행했을 때 출력이 같고 기존 활동·기자재·준비물·약품 연결 데이터와 검토 엑셀이 보존되는지 대조한다.
- **화면 검증** — PC·모바일에서 한 단계, 여러 단계, 하위 활동, 미확인을 확인한다. 최초 목록에서는 활동·성취기준 JSON만 요청하는지, 과정 로딩 실패·재시도·상세 전환 중에도 올바른 활동과 약품 정보가 표시되는지 검사한다. 기존 검색·정렬·필터 및 선택 로딩 검증도 실행한다.
- **배포 준비** — [사이트 전용 ZIP 파일 목록](../scripts/package_github_pages.py)에 과정 JSON을 반영한다. 루트 Pages 워크플로의 게시 대상은 `site/dist`다. 이번 작업의 산출물은 이 계획서이며, 실제 게시 확인은 이후 배포 시점에 한다.
