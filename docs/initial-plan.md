# 중학교 과학 교과서 탐구·실험 준비물 데이터베이스 구축 계획서

## 1. 사업 목적

2022 개정 교육과정 중학교 과학 교과서를 대상으로 성취기준별 탐구·실험·활동과 준비물을 구조화하여, 교사가 수업 준비 단계에서 필요한 정보를 빠르게 검색·필터링·집계할 수 있는 웹 기반 자료를 구축한다.

본 시스템은 별도의 표준 실험 체계를 새로 정의하지 않는다.

모든 실험·활동 정보와 준비물 수량은 **실제 교과서에 제시된 내용을 기준**으로 구축하며, 여러 출판사의 교과서 자료를 동일한 성취기준 아래에서 비교할 수 있도록 한다.

---

# 2. 기본 원칙

## 2.1 성취기준 중심으로 구성한다

데이터의 핵심 분류 단위는 실험명이 아니라 **교육과정 성취기준**이다.

기본 구조는 다음과 같다.

```text
학년
└─ 영역/단원
   └─ 성취기준
      ├─ 천재교육
      │   ├─ 탐구·실험·활동 A
      │   └─ 탐구·실험·활동 B
      │
      ├─ 비상교육
      │   └─ 탐구·실험·활동 C
      │
      └─ 동아출판
          └─ 탐구·실험·활동 D
```

동일한 과학 개념을 다루는 활동이라도 출판사가 다르면 별도의 교과서 활동으로 취급한다.

---

## 2.2 교과서에 존재하는 정보만 기록한다

다음과 같은 임의의 정보는 추가하지 않는다.

- 표준 실험명 임의 생성
- 교과서 활동들을 AI가 판단하여 하나의 실험으로 통합
- 교과서에 없는 준비물 추가
- 교과서에 없는 준비 수량 추정
- 경험에 따른 권장량 추가
- 임의 안전등급 부여

따라서 데이터의 기본 원칙은 다음과 같다.

> 교과서에 있으면 기록하고, 교과서에 없으면 비워 둔다.

---

## 2.3 출처를 추적할 수 있어야 한다

모든 활동은 최소한 다음 정보를 가진다.

- 교육과정
- 학년
- 성취기준 코드
- 성취기준 내용
- 출판사
- 교과서명
- 페이지
- 활동명
- 준비물
- 원문 근거

이를 통해 데이터 오류가 발견되었을 때 해당 교과서 페이지까지 다시 확인할 수 있게 한다.

---

# 3. 전체 데이터 구조

전체 구조는 다음과 같이 설계한다.

```text
성취기준
    │
    ├── 교과서 A
    │      │
    │      ├── 활동 1
    │      │    ├── 준비물
    │      │    └── 수량
    │      │
    │      └── 활동 2
    │
    ├── 교과서 B
    │      └── 활동 3
    │
    └── 교과서 C
           └── 활동 4
```

여기서 핵심 관계는 다음과 같다.

```text
achievement_standard
        ↓
textbook_activity
        ↓
activity_material
        ↓
textbook_quantity
```

별도의 `experiment_master` 계층은 두지 않는다.

# 4. 데이터 ID 설계

## 4.1 성취기준 ID

교육과정의 공식 성취기준 코드를 그대로 기본 식별자로 사용한다.

예:

```json
{
  "achievement_code": "9과○○-○○",
  "achievement_text": "..."
}
```

성취기준 코드가 가장 안정적인 상위 연결점이 된다.

---

## 4.2 교과서 ID

같은 출판사라도 저자 또는 판본이 구분될 수 있으므로 교과서를 고유하게 식별한다.

예:

```text
TXT-G1-CHEONJAE-JDH
TXT-G1-VISANG
TXT-G1-DONGA
```

저자 구분이 필요한 경우에도 확장 가능하게 한다.

---

## 4.3 활동 ID

각 교과서의 탐구·실험·활동에는 별도의 ID를 부여한다.

예:

```text
ACT-G1-CJ-0001
ACT-G1-CJ-0002
ACT-G1-BS-0001
```

활동 ID는 이후 준비물 수량 데이터가 추가될 때 핵심 연결키가 된다.

# 6. 준비물 데이터 정규화

검색과 집계를 위해 준비물 명칭은 별도로 정규화한다.

예를 들어 원자료에 다음처럼 표현될 수 있다.

```text
전자 저울
전자저울
전자 저울 1대
```

검색용 표준명은 다음과 같이 통일한다.

```json
{
  "raw_name": "전자 저울",
  "normalized_name": "전자저울"
}
```

단, 원문 자체를 삭제하지 않는다.

따라서 두 값을 함께 보존한다.

```text
원문 표현
+
검색·집계용 표준 표현
```

이 원칙은 화학약품에도 동일하게 적용한다.

# 7. 교과서 추가 확장

새로운 교과서를 확보하면 기존 성취기준 아래에 새로운 활동을 추가한다.

예:

```text
[9과XX-XX]

천재교육
 ├─ 활동 A
 └─ 활동 B

비상교육
 ├─ 활동 C
 └─ 활동 D

동아출판
 ├─ 활동 E
 └─ 활동 F

미래엔
 └─ 활동 G
```

기존 데이터를 수정하거나 다른 출판사의 활동과 합칠 필요가 없다.

따라서 향후 출판사 또는 교과서가 추가되어도 구조 변경 없이 확장할 수 있다.

# 8. 교과서별 필요 수량 데이터 확장

## 8.1 기본 원칙

준비물 수량 역시 **교과서에 제시된 수량만 기록**한다.

예:

```text
전자저울 1대
눈금실린더 1개
염산 20 mL
```

교과서에서 수량을 확인할 수 없는 경우에는 임의로 채우지 않는다.

```json
{
  "quantity": null
}
```

---

## 8.2 활동별 수량 연결

수량 데이터는 성취기준이나 임의의 표준 실험에 연결하지 않는다.

반드시 **특정 교과서의 특정 활동**에 연결한다.

예:

```json
{
  "activity_id": "ACT-G1-CJ-0001",

  "materials": [
    {
      "name": "전자저울",
      "quantity": 1,
      "unit": "대",
      "basis": "group"
    },
    {
      "name": "염산",
      "quantity": 20,
      "unit": "mL",
      "basis": "group"
    }
  ]
}
```

---

# 9. 수량 기준 종류

교과서 내용을 정확히 표현하기 위해 기준 단위도 기록한다.

예:

```text
1인당
1조당
1학급당
실험 전체
```

데이터에서는 다음과 같이 표현한다.

```json
{
  "quantity": 1,
  "unit": "개",
  "basis": "group"
}
```

가능한 값 예:

```text
student
group
class
activity
```

교과서에서 기준을 명확히 판단할 수 없는 경우에는 값을 추정하지 않는다.

# 10. 반별 준비물 계산

교과서 수량 데이터가 확보된 활동에 대해서는 프론트엔드에서 자동 계산한다.

사용자 입력 예:

```text
학급 수: 3
학급당 학생 수: 24
1조: 4명
```

계산:

```text
24명 ÷ 4명 = 6조

6조 × 3학급
= 총 18조
```

교과서가 다음과 같이 제시했다면,

```text
전자저울 1대/조
시험관 3개/조
염산 20 mL/조
```

웹에서는 다음과 같이 계산한다.

```text
전자저울     18대
시험관       54개
염산         360 mL
```

계산값과 교과서 원문 수량을 구분하여 표시한다.

```text
[교과서 기준]
염산 20 mL / 조

[입력 조건에 따른 계산]
18조 → 총 360 mL
```

추가 여유분이나 교사의 경험적 권장량은 자동으로 더하지 않는다.

---

# 11. 화학약품 데이터 연결

화학약품의 안전·분류 데이터는 교과서 데이터와 별도의 공식 자료에서 구축한다.

구조:

```text
교과서 준비물
    ↓
화학약품 여부 확인
    ↓
chemical_id
    ↓
공식 화학물질 정보
```

예:

```json
{
  "material_name": "염산",
  "chemical_id": "CHEM-HCL"
}
```

그리고 별도의 화학약품 데이터에서 연결한다.

```json
{
  "chemical_id": "CHEM-HCL",
  "name": "염산",
  "classification": "...",
  "label": "...",
  "source": "공식 자료"
}
```

교과서 데이터와 안전 데이터의 출처를 혼합하지 않는다.

# 12. 웹 서비스 주요 기능

## 12.1 성취기준 탐색

```text
중학교 1학년
→ 영역/단원
→ 성취기준
→ 교과서별 활동
```

---

## 12.2 출판사 필터

예:

```text
☑ 천재교육
☑ 비상교육
☐ 동아출판
☐ 미래엔
```

복수 선택이 가능하도록 한다.

---

## 12.3 준비물 검색

검색 예:

```text
전자저울
```

결과:

```text
전자저울이 필요한 모든 교과서 활동
```

---

## 12.4 화학약품 검색

검색 예:

```text
염산
```

결과:

```text
염산을 사용하는
모든 성취기준
모든 출판사
모든 활동
```

을 확인할 수 있게 한다.

---

## 12.5 성취기준별 비교

특정 성취기준을 선택하면 출판사별 활동을 한 화면에서 보여준다.

예:

```text
성취기준 9과XX-XX

천재교육
- 활동 A
- 활동 B

비상교육
- 활동 C

동아출판
- 활동 D
- 활동 E
```

---

## 12.6 활동별 준비물

```text
활동명
교과서 페이지
출판사

준비물
──────────
전자저울
눈금실린더
금속 조각
물
```

수량 데이터 구축 이후에는:

```text
전자저울    1대/조
눈금실린더  1개/조
물          50 mL/조
```

형태로 확장한다.

---

## 12.7 반별 준비물 계산

사용자가 다음을 입력한다.

```text
학급 수
학생 수
조당 학생 수
```

그 결과 해당 활동의 전체 준비량을 계산한다.

---

## 12.8 전체 준비물 목록

선택한 범위에서 중복 준비물을 합산한다.

예:

```text
중1
물질의 특성
천재교육
전체 활동

전자저울
눈금실린더
시험관
비커
스포이트
염산
에탄올
...
```

수량 데이터 구축 이후에는 총수량 계산까지 확장한다.

# 14. 데이터 파일 역할

### achievements.json

교육과정 성취기준 정보

### activities.json

출판사별 교과서 탐구·실험·활동 정보

### materials.json

준비물 명칭 정규화 및 분류

# 15. 구축 단계

## Phase 1. 스키마 확정

목표:

```text
성취기준
→ 교과서
→ 활동
→ 준비물
```

구조 확정

주요 작업:

- JSON Schema 확정
- ID 규칙 확정
- 필수/선택 필드 정의
- 원문 보존 필드 정의

---

## Phase 2. 기존 PDF JSON 변환

현재 확보한 PDF 표를 구조화한다.

작업:

1. 표 추출
2. 행 구조 복원
3. 성취기준 연결
4. 출판사 구분
5. 활동명 추출
6. 준비물 분리
7. JSON 생성

---

## Phase 3. 데이터 정규화

다음 항목을 정리한다.

- 출판사명
- 교과서명
- 성취기준 코드
- 준비물명
- 단위 표현

단, 원문 정보는 별도로 유지한다.

---

## Phase 4. 데이터 검증

자동 검증:

- 필수 필드 누락
- 잘못된 성취기준 코드
- 활동 ID 중복
- 교과서 ID 오류
- 빈 준비물
- 중복 레코드

사람 검증:

- PDF 원문과 활동명 비교
- 준비물 누락 확인
- 성취기준 연결 확인
- 교과서 페이지 확인

---

## Phase 5. 웹 MVP 구축

1차 MVP 기능:

- 학년 선택
- 성취기준 선택
- 출판사 필터
- 활동 목록
- 준비물 표시
- 준비물 검색
- 화학약품 검색

이 단계까지는 수량 데이터가 없어도 서비스 가능하다.

---

## Phase 6. 교과서 직접 검증 및 확장

실제 교과서를 확인하여 기존 자료의 내용을 보완한다.

특히 다음 정보를 추가한다.

```text
교과서 정확한 페이지
정확한 활동명
준비물 상세
교과서에 표시된 준비 수량
수량 기준
```

---

## Phase 7. 수량 계산 기능 추가

교과서 수량 데이터가 충분히 확보된 이후 다음 기능을 추가한다.

- 학생 수 입력
- 조당 학생 수 입력
- 학급 수 입력
- 조 수 자동 계산
- 활동별 전체 준비량 계산

---

## Phase 8. 화학약품 정보 연결

사용자가 제공하는 공식 근거 데이터를 바탕으로 화학약품 마스터 데이터를 구축한다.

기능:

- 화학약품 자동 식별
- 분류 정보 표시
- 안전표지 표시
- 공식 출처 표시

# 16. 품질 관리 원칙

각 데이터에는 상태를 둘 수 있다.

```text
extracted
verified
quantity_verified
```

예:

```json
{
  "activity_id": "ACT-G1-CJ-0001",

  "verification": {
    "activity": "verified",
    "materials": "verified",
    "quantity": "not_checked"
  }
}
```

따라서 PDF에서 자동 추출한 데이터와 실제 교과서를 직접 확인한 데이터를 구분할 수 있다.

---

# 17. 업데이트 원칙

새로운 교과서 데이터가 생기면 기존 데이터 구조를 수정하지 않고 활동 레코드를 추가한다.

```text
새 출판사 추가
→ textbook 추가

새 탐구활동 확인
→ activity 추가

준비물 확인
→ material 추가

수량 확인
→ quantity 추가
```

이를 통해 초기 PDF 데이터에서 시작해 실제 교과서 기반의 데이터셋으로 단계적으로 정밀도를 높인다.

---

# 18. 하지 않는 것

초기 시스템에서는 다음 기능을 포함하지 않는다.

- 사용자 로그인
- 교사별 계정
- 학교별 재고관리
- 교사별 수정 데이터 저장
- 임의 실험 추천
- AI가 생성한 준비물
- 경험적 권장 수량
- 별도의 표준 실험 분류 체계
- 복잡한 DB
- 별도 백엔드 서버

핵심 기능에 집중한다.

# 19. 최종 목표 사용자 흐름

교사가 사이트에 들어온다.

```text
중학교 1학년
↓
물질의 특성
↓
성취기준 선택
↓
천재교육 선택
↓
교과서 탐구활동 확인
↓
준비물 확인
```

수량 데이터가 있는 경우:

```text
24명

3개 학급
↓
총 18조
↓
전체 준비물 자동 계산
```

화학약품이 포함된 경우:

```text
염산
↓
공식 화학약품 정보 연결
↓
분류·표기 확인
```

# 20. 핵심 설계 요약

본 시스템의 데이터 구조는 다음 한 줄로 요약할 수 있다.

> **교육과정 성취기준을 중심으로 각 교과서에 실제 제시된 탐구·실험·활동과 준비물을 기록하고, 이후 동일한 교과서 활동에 교과서 기재 수량과 공식 화학약품 데이터를 단계적으로 연결한다.**

따라서 최종 구조는 다음과 같다.

```text
2022 개정 교육과정
        ↓
      학년
        ↓
     성취기준
        ↓
    출판사/교과서
        ↓
   탐구·실험·활동
        ↓
      준비물
        ↓
 교과서 기재 필요 수량
        ↓
  공식 화학약품 정보
```

**성취기준이 중심이고 교과서 활동이 실제 데이터의 최소 단위**라는 원칙을 유지한다.
